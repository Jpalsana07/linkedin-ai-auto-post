Shipping the boring parts.

I’m building an AI automation workflow for a client project, and this week it moved from “works on my laptop” to something that can sit in front of real people.

The flow handles incoming requests, classifies them, drafts a response, and routes edge cases to me instead of guessing.

I shipped the first end-to-end version with Claude API and Node.js, then wrapped the slow bits in a simple queue so one request wouldn’t block the next.

The good news: average turnaround dropped from 38 seconds to 14 seconds.

The bad news: the draft quality is still uneven on messy inputs.
Short messages do fine.
Long, multi-part requests still need a human pass.

That showed up fast once I started testing with real examples instead of clean demo text.

I also found one expensive mistake: the bot was retrying the same failed call three times, which made the logs look busy and the cost look weird.

The lesson is simple:
automation gets useful when it handles the unglamorous middle, not just the happy path.

If it can sort, route, and fail cleanly, people will actually trust it.

What part of an AI workflow do you think should stay human?
