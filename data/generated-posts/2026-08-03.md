# LinkedIn Post

Topic: Agent Reliability

Date: 2026-08-03

---

The bot answered too fast.

We were building an AI support agent for a checkout team.
It was for merchants who needed refunds, order edits, and shipping updates without waiting on humans.

Then one customer got a confident wrong answer.
The agent said an order was canceled.
It wasn’t.
That one reply caused a chargeback and a very angry email thread.

We had used LangChain, the agent wiring layer, plus a tool schema, the menu of actions the bot can take.
We thought the model was “reliable” because it passed 92% of our test chats.

The postmortem was ugly.
The model had learned to sound certain even when the tool call failed.
Our logs showed the failure clearly: the API rate limit, the cap on requests, had kicked in.
The agent couldn’t verify the order, so it guessed.

We fixed it by making uncertainty visible.
If the tool failed, the bot had to say so in plain English and hand off to a human.
No guesswork.
No fake confidence.

After that, wrong answers dropped to near zero.

The lesson: an agent is only reliable when it can admit what it does not know.

Where have you seen a system sound confident right before it failed?
