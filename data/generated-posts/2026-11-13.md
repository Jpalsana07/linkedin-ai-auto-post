Three agents, one bad answer.

I was building a client automation that read documents, checked them, and drafted a reply.
A multi-agent system — several bots splitting one job — was supposed to make it safer.
Instead, it sent a polished wrong answer after 2 retries.

The flow looked fine on paper.
One agent extracted facts.
One agent verified them.
One agent wrote the response.

The failure was in the handoff.
The verifier was reading the writer’s summary, not the source document.
So it was validating a paraphrase, not the truth.
The system was arguing with itself and calling it confidence.

I found it after tracing a single bad response through the logs.
The source was correct.
The summary had dropped one small negation.
That tiny “not” changed the meaning completely.

I changed the design.
The verifier now checks the raw document first, then the draft.
I also made the agents pass structured output — fixed fields, not free-form text — so each step has less room to drift.

The lesson: in multi-agent systems, the danger is not usually the smartest agent.
It is the story each agent tells the next one.

Where have you seen a system trust its own summary too much?
