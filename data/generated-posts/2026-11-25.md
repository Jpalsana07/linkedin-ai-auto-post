The tests were green.
The feature was broken.

I was building a small admin flow for a client project.
Claude Code was helping me write the React and Node.js pieces, and I trusted the first pass too much.

The bug was boring and ugly.
A form looked fine, saved fine, and only failed when a rare edge case hit the validation logic.

I had asked the coding agent to "clean up" the code.
It did exactly that.
It also simplified away one guard clause — the tiny check that stopped bad data from slipping through.

The worst part was how convincing it looked.
The component was shorter.
The diff was tidy.
The tests still passed because they only covered the happy path — the normal case where everything goes right.

The fix took 20 minutes.
The postmortem took longer.

Now I treat AI code like a fast junior teammate, not a final reviewer.
It is great at moving code quickly.
It is terrible at noticing the one line that protects the edge case.

The lesson: speed is cheap, but review is where the real work happens.

What do you make AI check for before you trust the code?
