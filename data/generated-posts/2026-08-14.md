# LinkedIn Post

Topic: MCP and Context Engineering

Date: 2026-08-14

---

MCP changed our design.

We were building an AI support agent.
The question was simple: give the model everything, or only what it asks for?

MCP, the Model Context Protocol, is a standard way for an app to expose tools and data to an AI.
Context engineering is the work of deciding what information the model sees, and when.

The tempting path was to stuff the prompt with customer data, docs, and 12 tools.
That felt powerful.
It also made answers slower, noisier, and harder to debug.

We chose the smaller path.
3 tools.
A tighter context window.
And one rule: the model had to ask before it got more data.

That meant a few extra round trips.
But it cut our prompt size by 68% and made failures obvious.
When the bot was wrong, we could see whether it chose the wrong tool or the right tool with bad input.

The lesson: give AI less by default, not because it is weak, but because clarity beats completeness.

This tradeoff matters less if your task is fully local, like summarizing one document.
It matters more when the AI can touch customer data, money, or actions you have to explain later.

Where have you seen “more context” make the system worse?
