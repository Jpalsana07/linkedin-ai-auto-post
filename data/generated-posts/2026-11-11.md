A shipping update on agent reliability.

I’m building a code-review agent for client and side projects.
It reads diffs, flags risky changes, and leaves a short review before I merge.

This week I shipped a stricter tool schema — the menu of actions the agent can take.
That cut bad tool calls from 14% to 3%.

The agent now has one job at a time.
Before, it could jump between reading files, searching context, and writing feedback in the same loop.
That looked flexible.
It also made it forget why it started.

I also added a hard stop on low-confidence answers.
If the model is unsure, it asks for one more file or returns “I need more context” instead of guessing.

The broken part is still memory.
It holds onto the last few steps too aggressively, so on larger diffs it sometimes repeats old reasoning and misses the new change.
That shows up mostly on 200+ line reviews.

The lesson: reliability is not making an agent smarter.
It is removing the places where it can improvise at the wrong time.

I’d rather get a shorter answer that stays honest than a confident one that drifts.

What do you trust more in agents: tighter constraints or more context?
