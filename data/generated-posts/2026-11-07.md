The bug came from my own prompt.

I was building a small internal feature for a client project.
Claude Code was helping me write the tests, the API glue, and a refactor in one pass.
Then a change that looked safe broke the flow in one place and passed everywhere else.

I spent 40 minutes blaming TypeScript, then React, then my backend.
TypeScript is the type system that catches shape mistakes.
React is the UI library for building screens.
The real issue was simpler: I had asked the coding agent to “clean up the handler” without giving it the edge cases I cared about.

It rewrote the code correctly for the happy path.
It also removed a tiny guard that only mattered when one field was empty.
The test still passed because I had only written the sunny-day version.

The root cause was not the model.
It was me using AI like a fast junior engineer instead of a tool that needs a sharp spec.

I fixed it by writing the failure cases first, then asking Claude Code to change only the smallest possible surface.
The next run took 6 minutes, not 40.

The lesson: AI coding is most useful when you tell it what must not break.

Where do you draw the line between letting AI move fast and forcing it to stay boxed in?
