MCP failed less. Context engineering won more.

I was building an assistant that had to read docs, inspect code, and answer one clear question without dragging the whole app into the prompt.

I tried two approaches: MCP, the Model Context Protocol, and old-school context engineering, which means hand-picking only the useful text for the model.

MCP was neat.
The tool list was clean.
The setup took about 30 minutes, and the agent could discover actions on its own.

But the first version still bloated the prompt.
It kept pulling in too much history, too many files, and too many irrelevant tool calls.

With context engineering, I spent 2 extra hours trimming the input.
I passed just the current file, the failing test, and one short summary of the last run.
The response time dropped from about 14 seconds to 6.
The answers also stopped drifting.

That was the real difference.

MCP is great for exposing tools.
Context engineering is what makes those tools usable.

My lesson: give the model less context than feels comfortable, then add back only what it proves it needs.

Which side do you trust more when the answer has to stay focused?
