# LinkedIn Post

Topic: MCP and Context Engineering

Date: 2026-10-20

---

MCP changed our prompts.

We were building an internal AI assistant for support.
The question was simple: do we stuff every tool and rule into the prompt, or let the model fetch context on demand?

MCP, the Model Context Protocol, is a standard way for an AI to ask for tools and data when it needs them.
That matters because the prompt has a hard limit, and every extra instruction makes the model slower and more confused.

The tradeoff looked like this:
put everything in the prompt for speed and simplicity,
or keep the prompt small and pay the cost of extra tool calls.

We chose smaller prompts plus MCP.
Why?

Because our biggest constraint wasn’t latency.
It was change.
Support docs moved every week, and a 400-line prompt was already stale before lunch.

With MCP, the assistant could pull the latest policy, ticket history, or order status only when needed.
Our average response time went up by 180 ms.
Our wrong-answer rate went down because the model stopped guessing from old context.

The lesson: when your information changes fast, let the model ask for it instead of cramming it into memory.

This tradeoff matters less for tiny workflows with stable rules and one or two tools.

Where have you chosen smaller prompts over “just include everything”?
