Topic: AI Agents

Date: 2026-09-04

---

I trusted the agent too much.

We were building an AI support rep to handle refund requests.
If it worked, it would save our team hours every week and answer angry customers in under a minute.

It looked great in demos.

Then one customer asked for a refund on two orders.
The agent grabbed the right order, but it sent the refund twice.

The bug was subtle.
We had given it a tool schema, the menu of actions the bot can take, but we never made the refund action idempotent, meaning safe to run twice.
So the agent did exactly what we asked, not what we meant.

One duplicated refund cost us $84 and a very awkward Slack thread.

We fixed it by moving the money-moving step behind a hard server check.
The agent could ask for a refund.
Only the backend could actually do it.

That changed how I think about AI agents.

The lesson is simple:
let the agent decide, but keep the irreversible action outside its hands.

What’s the riskiest action you’d never let an agent do alone?
