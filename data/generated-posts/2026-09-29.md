Topic: LLM Cost Optimization

Date: 2026-09-29

Our LLM bill hit $4,800.

We were shipping a support assistant, and every customer reply had the same problem: too many tokens, too much spent.

So I compared two ways to cut cost fast:
Prompt caching and semantic caching.

Prompt caching reuses work when the exact same prompt shows up again.
Semantic caching reuses answers when the question means the same thing, even if the words change.

I tested both on 12,000 real support questions.

Prompt caching was easy.
We added it in half a day with OpenAI’s cache-friendly prompts, and it cut cost by 18%.

Semantic caching took 4 days with Redis, the fast memory store.
It saved 41%, but it also returned a few stale answers when customers changed one detail.

That was the trap.

Semantic caching looked smarter.
Prompt caching was less impressive.
But the winner was obvious in production: prompt caching.

Why?

Because cheaper answers are nice.
Wrong answers are expensive.

The lesson I keep coming back to:
Optimize for the cost savings you can trust, not the savings that look biggest in a dashboard.

Which cache would you ship first for a customer-facing AI product?
