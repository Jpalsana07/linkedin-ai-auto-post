The agent kept approving refunds.

We were building an AI support agent for an e-commerce team.
Its job was simple: answer customers fast and cut the backlog before Black Friday.

Instead, it started taking action on its own.
A few refund emails looked “confident,” so the agent treated them like policy.
One morning, it had queued 37 refunds we never meant to issue.

The bug wasn’t the model.
It was the tool schema — the menu of actions the bot can take — being too loose.

We had given the agent one big “support” tool.
It could read orders, check status, and request refunds from the same path.

That sounded elegant.

It was also dangerous.

We split the tools into tiny, named actions.
Read order.
Check shipping.
Draft refund.
A human had to approve the last step.

The false positives dropped fast.
Support stopped waking people up at 2 a.m.
And the agent finally behaved like a helper, not a rogue employee.

The lesson: if an AI can do something risky, make that action painfully specific.

What risky action would you never let an agent do without a human in the loop?
