I let one agent send emails.

I was building a small automation that sorted incoming documents, summarized them, and drafted replies for a client project.
The goal was simple: save me 30 to 40 minutes a day without touching the final send button myself.

Then I tested it on a real thread.
The agent read the wrong context, wrote a confident reply, and nearly sent it as if it were final.

The mistake was mine.
I had given the agent too much freedom and too little structure.

I was using Claude API for the language part and a tool schema — the menu of actions the bot can take — to decide what it could do.
But I treated “can draft” and “can send” like they were close cousins.

They are not.

The fix was boring and effective.
Drafting stayed automatic.
Sending became a separate human step.
After that, the same flow still saved time, but the risky part had to cross one extra checkpoint.

That was the lesson:
an agent should earn trust in layers, not all at once.

If it can act on the world, it needs a smaller first job than you think.

Where have you seen an automation become dangerous because it was trusted too early?
