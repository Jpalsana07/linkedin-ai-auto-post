# LinkedIn Post

Topic: React Shipping Stories

Date: 2026-10-19

---

This week got real.

We’re building a React dashboard for ops teams who need to spot broken workflows fast.

This week I shipped the new incident timeline, the part that shows what changed, when, and who touched it.

It replaced a messy table that nobody trusted.

The first version looked fine in Storybook, the UI preview tool.

In production, it was slow.

A page with 120 events took 1.8 seconds to render, and the frame rate dropped hard when you scrolled.

So I rebuilt the list with windowing, which only renders the rows on screen.

That cut render time to 240 milliseconds.

But one thing is still broken: the filters reset every time you switch tabs.

That sounds small.

It isn’t.

Ops people use filters to answer one question: what changed right before the incident?

If that state disappears, the timeline becomes decoration.

The lesson I keep relearning: shipping the visible part is not enough.

If the state behind it is fragile, people won’t trust the product.

What’s the first thing you’d fix in a dashboard: speed, or state that never resets?
