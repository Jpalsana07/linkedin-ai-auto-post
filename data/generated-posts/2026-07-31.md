MCP beat our prompt glue.

We were building an internal assistant that could read docs, search tickets, and draft replies.
The problem was simple: the model kept forgetting which tools existed, and our prompts kept growing.

We tried two approaches.

First: hand-rolled context engineering.
That means we stuffed the right instructions, tool names, and examples into the prompt ourselves.
It took 2 weeks, and every new tool meant another brittle prompt edit.

Then we switched to MCP, the Model Context Protocol.
That’s a standard way to let the model discover tools instead of us hardcoding every path.
We had it wired to Slack, GitHub, and our docs search in 3 days.

The difference showed up fast.
Prompt size dropped by 38%.
Tool-call failures fell from 11% to 2%.
And onboarding a new tool stopped being a rewrite.

My winner is MCP.

Not because prompts are bad.
Because context engineering should shape the conversation, not become the product.

The lesson: when the problem is tool sprawl, pick the standard that makes tools easy to add.
