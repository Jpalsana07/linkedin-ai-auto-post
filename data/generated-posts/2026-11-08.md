# LinkedIn Post

Topic: AI Coding Hype vs Reality

Date: 2026-11-08

---

AI coding is not the bottleneck.

The sales pitch is simple:
type less, ship more, let the model do the boring parts.

My contrarian take:
the hard part is still judgment, not typing.

I use Claude Code every day to draft tests, review diffs, and scaffold boring CRUD work.
That part is real.
It saves me maybe 30 to 60 minutes on a normal day.

But on one client build, the model wrote a clean-looking auth flow in under 5 minutes.
The code ran.
The bug was in the edge case around token refresh, and it only showed up after a few manual retries.

That was the moment I got reminded:
AI is great at producing code that looks finished.
It is much worse at knowing what must never break.

The strongest counterargument is fair.
If you are starting from zero, AI can help you move fast enough to finish things you might never have shipped alone.
I’ve felt that too.

But the lesson is the same:
AI should compress the first draft, not replace your understanding.

If you treat it like a junior pair programmer, it helps.
If you treat it like a senior engineer, it will eventually hand you a polished mistake.

Where have you seen AI help speed up the wrong part of the work?
