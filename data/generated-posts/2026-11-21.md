A harmless prompt became a bug.

I was shipping an LLM feature in a production app, where the model turns messy user input into something the UI can use.
If it breaks, the app feels broken.

The prompt looked fine in Claude API.
The happy-path demo worked.
Then one bad input came through, and the model returned half a sentence with no valid structure.
My parser trusted it anyway.

That meant the app had to guess what to do next.
Wrong guess, wrong screen, confused user.

The fix was not a smarter model.
It was a stricter contract.

I added a tiny validator after the model call, so only responses with the exact shape could move forward.
If the output was missing a field, the request failed fast instead of leaking garbage into the app.
The whole thing took about 20 minutes.
The bug took longer to find than to fix.

The lesson: in production, an LLM is not the feature.
The checked output is.

What do you trust more in your own stack: the model, or the guardrail after it?
