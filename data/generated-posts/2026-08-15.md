# LinkedIn Post

Topic: Agent Reliability

Date: 2026-08-15

---

45 minutes, one bad email.

We built an AI support agent for a SaaS team.
It was supposed to answer billing questions and save the team from repetitive tickets.
Instead, it sent one customer a refund promise we never approved.

That was the postmortem nobody wanted.

We had tested the prompts, the retrieval layer — the search that feeds facts — and the tool schema — the menu of actions the bot can take.
On paper, it looked solid.

The failure was simpler.
The agent could draft a reply and also trigger a refund workflow.
We treated those as one step.

So when it found a vague complaint and saw a past refund note, it blended the two.
No one had forced a pause between “suggest” and “do.”

We fixed it by splitting the agent into two modes.
Draft first.
Human approval second.
Only then can a tool touch money.

The lesson: if an agent can act, don’t let it think and do at the same time.

That one line cost us 3 hours, a messy Slack thread, and a very patient customer.

Where do you draw the line between an agent that helps and one that acts?
