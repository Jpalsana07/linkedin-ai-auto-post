Date: 2026-11-03

I shipped a bad answer once.

It was inside a production web app, and the reply had to be useful on the first try.
If it missed, a real user would trust the wrong thing and move on.

I had an LLM feature running through Claude API, with a small validation step before the answer went out.
The output looked fine in testing.
In production, the model gave a polished response that was still wrong.

The bug was simple.
I was validating the shape of the text, not the facts inside it.

So the app kept accepting answers that were well-formed but useless.
No crash.
No warning.
Just confident nonsense.

I added a second pass: the model had to restate the key fields, and if they drifted, the response was rejected and retried.
That extra check added about 300 ms, but it saved the user from bad output more than once.

The lesson: in production, “looks right” is not the same as “is right.”

What do you trust more in LLM apps: a clean response, or a checked one?
