# LinkedIn Post

Topic: AI Coding Hype vs Reality

Date: 2026-11-17

---

This week, I shipped the agent to one client flow.
It reviews a draft, writes code, runs tests, and hands me a PR.

I built it as a solo engineer, with Claude Code doing the heavy lifting on writes and reviews.
The app around it is still the same stack I use everywhere: React, Next.js, Node.js, PostgreSQL, and GitHub Actions for the scheduled bits.

The good part: review time dropped from about 40 minutes to 12.
The bad part: the agent still misses small edge cases when the prompt gets too broad.

That was the real lesson this week.

AI coding is fast at first pass.
It is much weaker when the task depends on hidden context, old decisions, or one weird line in a file from last month.

I spent less time typing and more time checking.
That is the part people skip when they talk about speed.

The metric moved.
The trust did not.

So I am keeping the agent on narrow tasks, where the input is clear and the output is easy to verify.
That is where it earns its keep.

What’s the best line between “let the agent write it” and “I need to inspect every line”?
