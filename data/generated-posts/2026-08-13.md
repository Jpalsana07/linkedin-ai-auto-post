# LinkedIn Post

Topic: Next.js in Production

Date: 2026-08-13

---

Next.js got real traffic.

I’m building a customer portal for small B2B teams.
This week, real users started clicking around it.

We shipped the first production pass in Next.js 14.
The biggest change was moving the dashboard from client-side rendering to server components, which means the page arrives with less JavaScript and feels faster on weak laptops.

Lighthouse went from 61 to 89.
First load dropped by 1.8 seconds.

That part felt great.

What’s still broken is more honest.
One report page still flashes a blank state for a split second.
And our caching strategy is not stable yet, so some pages are fresh and some are weirdly stale.

I used to treat shipping like a finish line.
This week reminded me it’s more like turning knobs while people are already using the thing.

The lesson: in production, a stack choice only matters when it changes what users feel.

What’s the first Next.js tradeoff you’d make differently after shipping to real users?
