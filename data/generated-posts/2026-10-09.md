# LinkedIn Post

Topic: Node.js at Scale

Date: 2026-10-09

---

Node.js is overrated at scale.

The popular story is simple:
Node is fast, easy to hire for, and perfect until “real traffic” shows up.

I believed that too.
Then I helped run a Node API serving 2 million requests a day.

The bottleneck was not JavaScript.
It was everything around it:
bad cache keys, noisy neighbors, and a database doing too much work.

We moved one hot path out of the request cycle and put BullMQ, a background job queue, on the slow tasks.
P95 latency dropped from 840 ms to 190 ms.

That was the surprise.

Node didn’t fail because it was Node.
It failed when we treated it like a place to do every job immediately.

My hot take:
Node scales fine when you use it as an orchestrator, not a warehouse.

The strongest counterargument is still real:
for CPU-heavy work, Node can get crushed by garbage collection and a single event loop.

True.

But most teams don’t lose sleep over the language.
They lose sleep over synchronous work hiding in request handlers.

What has broken first for you at scale: the runtime, or the design?
