Topic: React Shipping Stories

Date: 2026-10-01

---

React on the server hurt less.

We were shipping a customer dashboard in Next.js.
The page had 12 widgets, and the first load felt sluggish.
Sales was waiting on this screen to close deals.

We had one decision to make:
render more in React, or send more plain HTML from the server.

React on the server means the browser gets ready-made page pieces.
Plain HTML means the browser gets text and layout first, then behavior later.

The tradeoff was simple.

More React gives a smoother app feel after load.
More HTML gives a faster first screen, which matters when a rep is staring at a blank page in a demo.

We chose the boring option: more HTML, less React.
That cut initial load by 38% and shaved about 900 ms off the first meaningful paint.
First meaningful paint is the moment the page looks useful.

Why?
Because our real constraint wasn’t polish.
It was trust.

A sales rep does not care that a dropdown is beautifully stateful if the page feels dead for 2 seconds.

I still like React.
I just think it should earn its place.

This tradeoff changes if your app is mostly interactive after login.
Then the smoother feel can matter more than the first load.

What would you optimize for first: instant page load or richer interaction?
