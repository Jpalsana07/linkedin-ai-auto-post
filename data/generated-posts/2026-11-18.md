I stopped letting agents see everything.

I was building an AI agent that handled a small internal workflow in a production web app.
The question was simple: should it get the full conversation, or only the part it needs?

Full context sounds safer.
More history, more clues, fewer chances to miss something.
But it also makes the agent slower, more expensive, and easier to distract.

So I chose narrow context.
The agent only got the current task, a short summary, and the tool schema — the menu of actions it can take.
That kept the prompt small and the output more reliable.

The tradeoff was obvious after a few runs.
Broad context helps when the task is fuzzy and human judgment matters.
Narrow context wins when the job is repetitive and the mistake cost is high.

I chose narrow because the constraint most people miss is not intelligence.
It is attention.
An agent that sees too much starts inventing relevance.

Where this breaks: if the task depends on long back-and-forth nuance, or hidden history buried across messages, trimming context too hard will hurt more than it helps.

The lesson: give agents less than you think, then add back only what they actually use.

What context would you cut first in your own agent?
