Topic: LLM in Production

Date: 2026-09-14

---

The bot answered the wrong customer.

We were building an LLM support assistant for a SaaS product.
It handled billing questions for 8,000 users.
Then it started giving confident, useful, completely wrong answers.

The scary part was the confidence.
It sounded like a great support rep right up until it invented refund rules.

We first blamed the prompt.
Then we blamed the model.
Then we added more context, more examples, and stricter instructions.

Nothing fixed it.

The root cause was simpler.
We had given the model our help docs, but not the current policy.
The retrieval layer — the search step that fetches source text — was pulling old pages from a cached index, a saved copy of the docs.

So the model wasn’t hallucinating from nothing.
It was faithfully repeating stale truth.

We found it by comparing bad answers against the exact doc version in the index.
One page had changed 11 days earlier.
The cache had not.

We rebuilt the index every deploy and added a freshness check before answers went out.

The lesson: when an LLM is wrong in production, check the inputs before you blame the intelligence.
