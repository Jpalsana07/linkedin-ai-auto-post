# LinkedIn Post

Topic: Agent Reliability

Date: 2026-10-08

---

We shipped an AI support agent.

It was for a B2B SaaS team handling refunds and account fixes.

On day 4, it confidently sent the wrong refund email to 37 customers.

We had built it with LangChain, a framework for wiring model steps together.

The agent looked fine in tests.

It failed in the messy middle: one customer had two accounts, and the tool schema — the menu of actions the bot can take — let it pick the refund path without checking which account was active.

So it grabbed the wrong order ID, then wrote a polite lie with perfect grammar.

We spent two days blaming the model.

Then we traced the logs and saw the real issue: the agent was making decisions before it had verified the customer’s identity.

That was the root cause.

Not “bad AI.”

Missing guardrails.

We fixed it by forcing a human-readable check before any money-moving action.

One simple rule changed everything: if the agent can cause damage, make it prove the facts first.

That sounds obvious now.

It felt expensive at 2 a.m.

What’s the guardrail you learned the hard way?
