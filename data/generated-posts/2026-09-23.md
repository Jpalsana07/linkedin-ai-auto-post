Topic: MCP and Context Engineering

Date: 2026-09-23

---

MCP beat the old plugin path.

We were building an AI assistant that had to read tickets, fetch docs, and create Jira issues without hand-holding.
The choice was MCP, the new tool connector standard, or a custom plugin layer.

With the plugin layer, every tool needed a one-off wrapper.
Three tools became 11 files, and every schema change meant another half day of fixes.

MCP was simpler.
One server exposed the tools, and the model could discover them with the same contract.
That cut setup from 2 days to 3 hours.

It also made context engineering cleaner.
Context engineering means choosing what the model sees, not dumping everything in.
With MCP, we could send only the ticket, the relevant doc, and the action menu.
Less noise.
Fewer hallucinated clicks.

The winner was MCP.
Not because it was trendy.
Because it made the tool boundary explicit, which kept the assistant easier to debug and cheaper to extend.

The lesson: when an AI needs tools, prefer the interface that makes the model’s choices visible.
