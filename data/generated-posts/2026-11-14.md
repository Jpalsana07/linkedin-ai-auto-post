The best automations are boring.

Most people want an AI workflow to feel smart.
A bot that reads, decides, and acts on its own.

I’ve found the opposite works better.
The best workflow is usually one clear step, one clear owner, and one escape hatch.

I built a small automation with Claude API and GitHub Actions — a free scheduler that runs code on a timer.
It processed a handful of documents, then handed me only the messy edge cases.

The first version tried to do everything.
Classify, summarize, route, and draft replies.
It looked impressive until one vague input sent it down the wrong path and I had to trace 4 steps to find where the mistake started.

So I cut it back.

Now the system does the dull part first, then asks for help only when it is unsure.
The result was less “AI magic” and more 10 minutes of calm fixes instead of 1 hour of guessing.

The hot take:
automation should remove decisions, not create new ones.

The strongest counterargument is obvious.
If humans still have to review everything, what is the point?

My answer is simple.
A workflow that saves 80 percent of the work is still worth more than a clever one that fails silently.

Where have you seen an “intelligent” workflow create more noise than help?
