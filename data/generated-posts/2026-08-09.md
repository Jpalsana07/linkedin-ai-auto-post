Topic: AI Agents

We trusted the agent too much.

We were building an internal assistant for a 40-person support team.
Its job was simple: read a ticket, check Stripe, and draft a reply.
Instead, it refunded the wrong customer twice in one afternoon.

The weird part was that the model looked confident.
It had access to the right tools.
It could search tickets, call Stripe, and write a response.
But it treated every step like a fresh guess.

We had built the tool schema — the menu of actions the bot can take — with no real guardrails.
So the agent could ask Stripe for a refund before it proved the customer was eligible.
One missing check, and we turned a helpful draft into a money leak.

We fixed it by making the workflow boring.
The agent had to verify identity first, then eligibility, then action.
After that, the refund mistakes dropped to zero over the next 3 weeks.

The lesson: an AI agent should ask for permission before it takes action.
Confidence is not the same as correctness.

Where would you put the hard stop in an agent you were shipping?
