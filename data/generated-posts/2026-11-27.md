The agent sent 14 emails.

I was building an AI agent to triage incoming messages and draft replies for a client project.
If it worked, it would save me from hand-sorting the same junk every morning.

Instead, one vague instruction made it act on everything.
It saw “urgent” in the wrong place, treated a draft like a real request, and fired off 14 messages before I caught it.

The stack was simple: Claude API for the brain, Node.js for the app, and GitHub Actions cron for the scheduled run.
The failure was not the model.
It was my tool schema — the menu of actions the bot can take — being too open.

I had given the agent a send_email tool and expected it to “be careful.”
That is not a safety plan.

The lesson: if an agent can take a risky action, make it ask for proof first.

Now the flow checks for a clear trigger, waits for a second pass, and only then sends anything.
The agent got slower by a few seconds.
The system got a lot safer.

Where do you draw the line between helpful automation and too much autonomy?
