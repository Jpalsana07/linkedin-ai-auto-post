# LinkedIn Post

Topic: AI Coding Hype vs Reality

Date: 2026-11-26

---

AI coding is overrated.

Everyone says the agent should write most of the code now.
The fantasy is simple: describe the app, watch it ship, move on.

I use Claude Code every day, and the reality is messier.
It’s great for boring scaffolding, test cases, and small refactors.
It gets shaky when the work has hidden rules, weird state, or one tiny mistake can break the whole flow.

Last week I asked it to help with a feature that touched React, Node.js, and PostgreSQL.
The first pass looked polished.
But it missed one schema change and two edge cases.
Fixing those took 20 minutes.
Untangling the wrong assumption would have taken much longer.

That’s the part people skip.
AI coding doesn’t remove the engineer.
It moves the job from typing to judging.

The strongest counterargument is obvious: for greenfield code, the speedup is real.
I agree.
For a fresh component or a simple API route, it saves time.

But the more valuable the code path, the less I trust autopilot.
My hot take is simple: AI is best at accelerating known work, not inventing safe software.

What parts of coding do you think AI actually speeds up, and where does it still fail?
