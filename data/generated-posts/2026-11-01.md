My bot answered with the wrong memory.

I was building an internal assistant for a client project, and it was supposed to pull the right notes before drafting replies.
Instead, it kept mixing old context with fresh requests.

The app used MCP, the Model Context Protocol, so the model could call tools and read the right files.
I also had context engineering, which is just deciding what the model sees, in what order, and how much of it.

The failure was sneaky.
The tool calls worked.
The answer looked confident.
But one stale document was still being sent in every request, so the model kept treating yesterday’s note as if it were current.

I spent a few hours blaming the prompt.
Then I checked the actual payloads and found the real problem: too much context, and the wrong context.

The fix was simple.
I stopped sending everything.
I made the tool return only the exact section needed, plus a short summary, and I added a small freshness check so older notes could not win by accident.

The lesson: with MCP, the model is only as good as the context you feed it.
Good prompts help, but clean context is what keeps the answer honest.

What do you trust more when an AI is wrong: the prompt, or the context?
